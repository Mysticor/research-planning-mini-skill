# 摘要补查：接口为空不是终点

Google Scholar 记录优先执行 [Description-only 规则](search-execution.md)：只读 Scholar 自身详情，不沿外链补摘要；snippet 不作摘要，无完整可核实 Description 则不进入100篇。已有同 DOI 摘要可复用。其他来源按下述流程补查。

初筛先核对文类和题名相关性；数据库的 article 分类也可能混入更正通知。书籍、目录、更正/撤稿通知单独记录其用途，不当普通研究论文填满100篇；重要更正要关联原论文，不直接丢弃。摘要缺失不能据此排除可能关键的研究。

按收益顺序分批执行，找到可核验的完整原始摘要就停止该篇补查：

1. **复用已取得记录。** 同一DOI在其他检索批次/导出里已有摘要时，先合并，不重复联网。`enrich_abstracts.py INPUT --supplement OTHER_RUN.json EXPORT.ris --output NEW.json` 会复用输入及补充文件的精确DOI摘要，再访问接口。保留来源和不同版本，不按相似标题自动拼接。
2. **精确DOI补查。** Crossref、OpenAlex、Semantic Scholar按实际可用性调用。Crossref发现检索必须显式相关性降序，不能把游标默认返回顺序当最相关。网络临时失败/429有限重试（内置至多3次；429间隔12/24秒并尊重Retry-After）；更长服务等待留到下批，不绕过限流。持续429时转其他来源，不反复撞同一端点。额外bulk端点并不保证解决限流。
3. **网页补查。** 模型用当前可用的网页/浏览工具执行 `DOI abstract`，无有效结果再查 `"完整题名" abstract`。优先打开出版社页，其次作者机构库、记录中实际提供的其他落地页，再考虑有来源的学术索引（如领域适用的RePEc/IDEAS）。OpenAlex的 `source_urls` 包含可能的机构库链接，即使它自身没有摘要也应检查。URL必须来自实际结果，不能凭经验拼出版物页面。某站403不表示其他独立来源也不可用；不用换身份或代理反复绕过同站限制。
4. **公开正文的作者摘要。** 合法可访问PDF/HTML时可定位作者原始Abstract，核对标题、作者、年份、DOI/卷页，记录页码与原件。没有DOI的正文需组合元数据核对；不能将自己的全文总结填进abstract。网页搜索返回短片段、推荐论文摘要、简介或页面description均不能当本篇完整摘要；特别注意出版社页面推荐区里的“Show abstract”。

将网页/PDF取得的原始摘要保存到项目的版本化JSON记录：doi、title、abstract、source、url、retrieved_at、abstract_locator、identity_check；另记实际阅读与筛选理由。作为 `--supplement` 再合并进文献库，避免下次丢失。仅有题名/摘要不匹配、截断、打不开、未完成检查的记录维持待查。自动接口脚本不等于网页工具；环境没有网页工具时明确这一步未执行。

每批保存查过哪些渠道、失败原因及下一步。首次补查使用上述可用路径，不无限搜索同一论文；遇到明确访问限制或有效路径已检查后列缺口；新线索/用户材料出现再恢复。没有真实摘要、未实际读过摘要或缺入围理由的记录不进入100篇。数量不足报告未完成，不凑数。网页补回成功率只报告实测样本，不向全领域外推。

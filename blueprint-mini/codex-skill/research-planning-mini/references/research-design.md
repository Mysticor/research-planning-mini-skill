# Executable research protocol
Each RQ: question, significance, hypothesis, expected observation (PLANNED),
alternative explanation, falsification condition, required evidence and test.
Reuse the early topic assessment of assumptions, alternative explanations and minimum feasible checks; update it with literature evidence and expand it into the protocol rather than restarting ideation.
Compare routes only when meaningful alternatives exist; otherwise record the justified route. Gate C follows the shared AUTO rule before detailed commitment.

Every method module: purpose, input/output, selected and alternative methods,
rationale, dependencies, assumptions, implementation requirements, validation,
risks and fallback. Make it actionable as an implementation specification.
Data blueprint: source/acquisition, formats/scale, metadata, labels/annotation/QC,
splits or equivalent, leakage, missingness, imbalance, versions/provenance,
permissions and context-relevant privacy/ethics. Separate AVAILABLE_DATA,
MISSING_DATA, CRITICAL_DATA_BLOCKER.

Experiment matrix has stable E IDs and RQ/hypothesis, purpose, inputs, methods,
baselines/controls, variables, metrics, statistics, expected evidence, falsifier,
outputs/assets/status. Consider only scientifically motivated benchmarks, ablations,
sensitivity, robustness, generalization, external/field/OOD validation, failures,
negative controls, cost and uncertainty. Review studies use extraction/synthesis
activities, never fictitious laboratory experiments.

Set SUCCESS, PARTIAL_SUCCESS, FAILURE/FALSIFICATION, GO/NO-GO, resource limits and
fallbacks before results. If physical validation fails, do not continue claiming
quantitative reconstruction; document a justified weaker route, if useful.
Freeze RESEARCH_BLUEPRINT_FINAL only after Gate D. Changes become deviations with
original/new plan, date, reason, before/after outcome knowledge and claim impact.
